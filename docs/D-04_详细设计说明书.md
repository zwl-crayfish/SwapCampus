#### 3.1.3 关键方法详述

**GoodsService.publishGoods(request, sellerId, images)**

```
输入: GoodsRequest, Long sellerId, MultipartFile[] images
处理:
  1. 生成商品UUID (IdUtil.fastSimpleUUID())
  2. 构建 Goods 实体: uuid, sellerId, categoryId, title, price, 等
  3. 计算折扣价: discountPrice = price * discount / 100
  4. goodsMapper.insert(goods)
  5. IF images != null AND images.length > 0:
       FOR EACH image:
         url = fileService.uploadImage(image, uuid)  // 上传到 MinIO
         goodsImageMapper.insert(new GoodsImage(uuid, url, i))
  6. RETURN goods
异常:
  - 图片超过9张: 前端限制
  - 图片超大: FileService 抛出 RuntimeException("图片上传失败")
事务: @Transactional
```

**FileService.uploadImage(file, goodsUuid)**

```
输入: MultipartFile file, String goodsUuid
处理:
  1. 检查 bucket 是否存在，不存在则创建
  2. 提取文件扩展名
  3. 生成对象名: "goods/{goodsUuid}/{newUuid}.{ext}"
  4. minioClient.putObject(bucket, objectName, inputStream, size, contentType)
  5. 拼接返回URL: endpoint/bucket/objectName
输出: String url
异常: IOException → RuntimeException("图片上传失败")
```

#### 3.1.4 商品搜索 SQL

```sql
SELECT * FROM goods
WHERE status = 1
  AND (title LIKE CONCAT('%', #{keyword}, '%')
       OR MATCH(title, description) AGAINST(#{keyword} IN BOOLEAN MODE))
  AND (#{categoryId} IS NULL OR category_id = #{categoryId})
ORDER BY
  CASE WHEN #{sortBy} = 'price' THEN price END,
  created_at DESC
LIMIT #{offset}, #{size}
```

#### 3.2.2 关键方法详述

**OrderService.createOrder(buyerId, goodsUuid, tradeMethod, meetLocation, meetTime)**

```
输入: Long buyerId, String goodsUuid, String tradeMethod, String meetLocation, String meetTime
处理:
  1. goods = goodsMapper.findByUuid(goodsUuid)
  2. 校验: goods != null, goods.status == 1, goods.sellerId != buyerId
  3. 生成订单UUID
  4. 构建 Order: uuid, goodsUuid, buyerId, sellerId, amount=goods.price, status=0
  5. orderMapper.insert(order)
  6. 更新商品状态: goods.status = 2 (已售出)
  7. goodsMapper.updateById(goods)
  8. RETURN order
事务: @Transactional
```

**OrderService.buyerConfirm(orderUuid, userId)**

```
输入: String orderUuid, Long userId
处理:
  1. order = orderMapper.findByUuid(orderUuid)
  2. 校验: order.buyerId == userId
  3. order.buyerConfirm = 1
  4. IF order.sellerConfirm == 1:
       order.status = 2  // 完成
       addCreditScore(buyerId, +2)
       addCreditScore(sellerId, +2)
  5. orderMapper.updateById(order)
事务: @Transactional
```

### 3.4 模块 D：认证模块 (Auth)

#### 3.4.1 JWT 认证流程

```
请求到达 → JwtAuthenticationFilter
              │
              ├── 无 Authorization Header → 继续（匿名访问）
              │
              └── 有 Bearer Token:
                    │
                    ├── Token 无效/过期 → 继续（匿名，后续SecurityConfig拦截）
                    │
                    └── Token 有效:
                          提取 userId, username, role
                          → 构建 UsernamePasswordAuthenticationToken
                          → 注入 SecurityContextHolder
                          → 后续 @PreAuthorize 可用
```

#### 3.4.2 JwtTokenProvider 关键方法

```java
// 生成 Token
public String generateToken(Long userId, String username, Integer role) {
    Map<String, Object> claims = new HashMap<>();
    claims.put("userId", userId);
    claims.put("username", username);
    claims.put("role", role);

    return Jwts.builder()
            .claims(claims)
            .subject(username)
            .issuedAt(new Date())
            .expiration(new Date(System.currentTimeMillis() + 86400000))
            .signWith(getSigningKey())  // HMAC-SHA256
            .compact();
}

// 验证 Token
public boolean validateToken(String token) {
    try {
        parseToken(token);
        return true;
    } catch (JwtException | IllegalArgumentException e) {
        return false;
    }
}
```

## 4 关键算法描述

### 4.1 算法：信用分增量计算

```
算法 CreditScoreUpdate(userId, delta)
输入: userId - 用户ID, delta - 增量 (正或负)
输出: 更新后的信用分

步骤:
  1. user = userMapper.selectById(userId)
  2. newScore = user.creditScore + delta
  3. IF newScore < 0:  newScore = 0
  4. IF newScore > 100: newScore = 100
  5. user.creditScore = newScore
  6. userMapper.updateById(user)
  7. RETURN newScore

复杂度: O(1) — 单条UPDATE
边界条件: delta为正负值时均需夹紧到 [0, 100]
```

### 4.2 算法：全文搜索（MySQL FULLTEXT）

```
算法 SearchGoods(keyword, categoryId, sortBy, sortOrder, page, size)
输入: 搜索参数
输出: 分页商品列表

步骤:
  1. 构建动态SQL (MyBatis <script>)
  2. IF keyword NOT NULL:
       添加条件: MATCH(title, description) AGAINST(keyword IN BOOLEAN MODE)
  3. IF categoryId NOT NULL:
       添加条件: category_id = #{categoryId}
  4. 添加状态条件: status = 1
  5. ORDER BY {sortBy} {sortOrder}
  6. LIMIT {(page-1)*size}, {size}
  7. 执行查询，返回结果

复杂度: O(log N) — 依赖全文索引
边界条件: keyword为空时退化为全表扫描（带分类索引优化）
```

## 6 异常处理与并发设计

| 场景 | 策略 |
|------|------|
| **重复下单** | 商品 status=1(在售) 时才能下单；下单后立即 status=2(已售出)，杜绝并发重复购买 |
| **订单取消** | 商品恢复 status=1；订单标记 status=-1（软删除） |
| **事务回滚** | Service 关键方法标注 `@Transactional`，异常时自动回滚 |
| **幂等性** | UUID 唯一约束保证消息和订单不重复 |
| **并发控制** | 基于数据库行锁（UPDATE 时自动加锁），未使用乐观锁（课程阶段不需要高并发） |
| **图片上传** | 单个上传失败不影响已成功的图片 |
