## 1 引言

### 1.1 编写目的

本文档旨在完整定义 SwapCampus 校园闲置物品交易平台的软件需求，作为后续概要设计、详细设计、编码实现、测试验收各阶段的基线依据。本文档的预期读者包括：

|------|------|
| 指导教师 | 评审需求完整性、合理性 |
| 开发团队（本组） | 指导设计、编码、测试 |
| 测试人员 | 编写测试用例、验收标准 |
| 后续维护者 | 理解系统功能边界 |

### 1.2 项目背景

北京林业大学校内每年产生大量闲置物品（教材、电子产品、生活用品等），当前通过微信群进行散点式交易，存在信息碎片化、信用难追溯、交易效率低等问题。学校学生处希望建设一个面向本校师生的闲置物品交易平台，以提高校内资源流转率，同时为同学提供安全、便捷的交易体验。

本项目是《软件工程（课程设计）》的课程项目（选题编号 T-02），要求以 3-4 人团队，在 2 周（14 天）集中实习期内，完成从立项到答辩的完整软件工程实践。

## 2 总体描述

### 2.1 产品愿景与定位

SwapCampus 是一个面向北京林业大学师生的 C2C 校园闲置物品交易平台。用户可通过 Web 端发布闲置物品、浏览购买二手商品、与买卖双方实时沟通，并基于学号实名 + 信用积分体系建立可信交易社区。

**核心价值主张**: 让校园闲置流转更安全、更高效、更可信。

### 2.2 产品功能概要

| 编号 | 功能 | 说明 |
|------|------|------|
| F01 | 用户注册与登录 | 学号实名注册 + JWT 鉴权 |
| F02 | 个人主页与信用分 | 个人信息管理、信用积分展示 |
| F03 | 商品发布 | 多图上传、分类、成色、价格 |
| F04 | 商品浏览与搜索 | 分类筛选、关键词搜索、排序 |
| F05 | 商品收藏 | 收藏/取消收藏、收藏列表 |
| F06 | 下单交易 | 下单、选择交易方式（面交/邮件柜） |
| F07 | 交易确认 | 买卖双方确认收货 |
| F08 | 订单评价 | 交易完成后打分评价 |
| F09 | 站内即时通讯 | WebSocket 实时聊天、图文消息 |
| F10 | 商品审核 | 管理员审核/下架商品 |
| F11 | 用户管理 | 管理员查看/禁用用户 |
| F12 | 举报处理 | 用户举报 → 管理员处理 |
| F13 | 数据仪表盘 | 管理员统计总览 |

### 4.2 功能详述（部分关键功能）

#### FR-01 用户注册

- **输入**: 学号、用户名、密码、真实姓名、手机号(选填)、邮箱(选填)
- **处理**: (1) 校验学号唯一性 (2) 校验用户名唯一性 (3) BCrypt 加密密码 (4) 创建 User 记录 (5) 创建 Wallet 记录 (6) 生成 JWT Token
- **输出**: TokenResponse (accessToken, userId, username, realName, role)
- **异常**: 学号重复、用户名重复

#### FR-04 发布商品

- **输入**: 标题、分类ID、价格、原价(选填)、成色(1-10)、交易方式、校区位置、描述、图片文件数组
- **处理**: (1) 生成商品UUID (2) 计算折扣价 (3) 保存 Goods 记录 (4) 上传图片到 MinIO (5) 保存 GoodsImage 记录
- **输出**: Goods 实体
- **异常**: 图片超过9张、图片超大、参数校验失败

#### FR-14 即时通讯

- **输入**: 发送者ID、接收者ID、消息内容、消息类型(TEXT/IMAGE)、关联商品UUID(可选)
- **处理**: (1) 生成消息UUID (2) 保存 Message 记录 (3) 通过 WebSocket STOMP 推送到接收者的 `/user/{id}/queue/chat`
- **输出**: WebSocket 推送 Message 对象
- **性能**: 端到端延迟 ≤ 200ms
- **异常**: WebSocket 连接断开 → 降级为 HTTP 轮询
