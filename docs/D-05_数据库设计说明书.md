## 1 引言

### 1.1 编写目的

本文档定义 SwapCampus 系统的数据库设计，涵盖概念模型（ER 图）、逻辑模型（关系模式）、物理模型（DDL + 数据字典）、索引策略、安全与备份策略。预期读者为后端开发人员和数据库管理员。

### 1.2 数据库选型与版本

| 属性 | 选择 |
|------|------|
| **DBMS** | MySQL 8.0 |
| **引擎** | InnoDB（全部表） |
| **字符集** | utf8mb4 + utf8mb4_unicode_ci |
| **时区** | Asia/Shanghai |

**选型理由**（参见 ADR-002）：
- 课程要求 MySQL 8
- InnoDB 支持事务、行锁、外键约束
- utf8mb4 支持 emoji 和生僻字
- 全文索引 (FULLTEXT) 支持中文商品搜索

## 3 逻辑模型

### 3.1 关系模式

使用 **R(属性1, 属性2, ..., 主键, 外键)** 格式表示。

```
user (id, student_id, username, password, real_name, avatar_url, phone,
      email, role, credit_score, status, created_at, updated_at)
  PK: id
  AK: student_id, username

category (id, name, icon, sort_order, status, created_at)
  PK: id

goods (id, uuid, seller_id, category_id, title, description, price,
       original_price, condition_level, is_bargain, trade_method,
       campus_location, view_count, favorite_count, status,
       created_at, updated_at)
  PK: id
  AK: uuid
  FK: seller_id → user(id)
  FK: category_id → category(id)

goods_image (id, goods_uuid, url, sort_order, created_at)
  PK: id
  FK: goods_uuid → goods(uuid)

orders (id, uuid, goods_uuid, buyer_id, seller_id, amount, trade_method,
        meet_location, meet_time, buyer_confirm, seller_confirm, status,
        buyer_rating, buyer_review, completed_at, created_at, updated_at)
  PK: id
  AK: uuid
  FK: goods_uuid → goods(uuid)
  FK: buyer_id → user(id)
  FK: seller_id → user(id)

favorite (id, user_id, goods_uuid, created_at)
  PK: id
  FK: user_id → user(id)
  FK: goods_uuid → goods(uuid)
  UK: (user_id, goods_uuid)

message (id, uuid, sender_id, receiver_id, goods_uuid, content,
         msg_type, is_read, created_at)
  PK: id
  AK: uuid
  FK: sender_id → user(id)
  FK: receiver_id → user(id)

wallet (id, user_id, balance, points, created_at, updated_at)
  PK: id
  FK: user_id → user(id)
  UK: user_id

report (id, reporter_id, goods_uuid, reported_user_id, reason,
        description, status, handler_id, handle_remark,
        created_at, handled_at)
  PK: id
  FK: reporter_id → user(id)

notification (id, user_id, title, content, is_read, created_at)
  PK: id
  FK: user_id → user(id)
```

### 3.2 范式说明

| 表 | 范式 | 说明 |
|------|------|------|
| user | 3NF | 所有非主属性完全函数依赖于主键 id |
| goods | 3NF | 分类信息通过 category_id 外键关联，无传递依赖 |
| orders | 3NF | 金额、状态等完全依赖订单主键 |
| message | 3NF | 消息内容完全依赖消息主键 |
| wallet | 3NF | user_id 唯一约束保证一个用户一个钱包 |

**全部表均达到 3NF**，无反范式冗余（课程项目数据规模小，无需反范式优化查询性能）。

## 5 索引与性能

### 5.1 索引清单

| 表 | 索引名 | 字段 | 类型 | 说明 |
|------|--------|------|------|------|
| user | PRIMARY | id | 聚簇 | 主键 |
| user | idx_student_id | student_id | 普通 | 学号查询 |
| user | idx_username | username | 普通 | 登录查询 |
| user | idx_status | status | 普通 | 管理员筛选 |
| goods | PRIMARY | id | 聚簇 | 主键 |
| goods | idx_uuid | uuid | 普通 | UUID查询(高频) |
| goods | idx_seller | seller_id | 普通 | 卖家商品列表 |
| goods | idx_category | category_id | 普通 | 分类筛选 |
| goods | idx_status | status | 普通 | 状态筛选 |
| goods | ft_title_desc | title, description | **FULLTEXT** | 全文搜索 |
| goods_image | idx_goods_uuid | goods_uuid | 普通 | 商品图片查询 |
| orders | idx_uuid | uuid | 普通 | 订单查询 |
| orders | idx_buyer | buyer_id | 普通 | 买家订单列表 |
| orders | idx_seller | seller_id | 普通 | 卖家订单列表 |
| orders | idx_status | status | 普通 | 状态筛选 |
| favorite | uk_user_goods | user_id, goods_uuid | **UNIQUE** | 防重复收藏 |
| message | idx_sender | sender_id | 普通 | 发件查询 |
| message | idx_receiver | receiver_id | 普通 | 收件查询 |
| message | idx_created | created_at | 普通 | 时间排序 |
| wallet | user_id | user_id | UNIQUE | 一对一关系 |
| notification | idx_user_read | user_id, is_read | 复合 | 用户未读通知 |
| report | idx_status | status | 普通 | 管理员筛选 |

### 5.2 性能预估

| 指标 | 课程阶段预估 | 假设条件 |
|------|-------------|----------|
| 用户数 | ≤ 10 | 3-4 组员 + 灰度用户 |
| 商品数 | ≤ 500 | 含种子数据 200 条 |
| 订单数 | ≤ 100 | 课程周期 2 周 |
| 消息数 | ≤ 2000 | 测试聊天 |
| 单表最大行数 | ≤ 2000 (message) | 正常范围 |
| QPS | ≤ 10 | 单人/少人测试 |

**Top 5 慢查询治理**（仅预留，课程阶段数据量不触发性能问题）：

| # | 查询 | 建议优化 |
|------|------|----------|
| 1 | 商品全文搜索 | FULLTEXT 索引已覆盖 |
| 2 | 订单列表(按买家) | idx_buyer + idx_status 复合索引 |
| 3 | 消息对话记录 | idx_sender + idx_receiver + idx_created |
| 4 | 管理员用户列表 | idx_status 筛选 + 分页 |
| 5 | 举报列表 | idx_status + 分页 |

## 6 安全与合规

### 6.1 权限设计

| 数据库账号 | 权限 | 用途 |
|-----------|------|------|
| `root` (本地开发) | ALL | 本地开发，仅 localhost 可访问 |
| `swapcampus_app` (生产) | SELECT, INSERT, UPDATE, DELETE | 应用连接（待创建） |
| `swapcampus_readonly` (生产) | SELECT | 数据分析（待创建） |

### 6.2 敏感字段处理

| 字段 | 处理方式 |
|------|----------|
| password | BCrypt 加密存储，API 返回前 set null |
| phone | 仅在个人中心和订单详情展示（认证用户可见） |
| email | 仅用户本人可见 |

### 6.3 审计与备份

| 策略 | 课程阶段 | 生产环境（预留） |
|------|----------|-----------------|
| 备份频率 | 每日手动 `mysqldump` | 每日自动 + 异地 |
| 备份保留 | Git 版本控制（SQL 文件） | 30 天滚动 |
| 审计日志 | 未实现（课程阶段） | 关键操作表（登录记录、管理员操作） |
| 恢复演练 | 重新执行 `db/schema.sql` | 定期演练 |

## 7 数据生命周期

| 表 | 保留策略 | 归档/销毁 |
|------|----------|-----------|
| user | 课程期间保留 | 课程结束后可删除 |
| goods | 课程期间保留 | 下架商品状态标记（软删除 status=-1） |
| orders | 课程期间保留 | 取消订单标记（status=-1） |
| message | 课程期间保留 | 不主动清理 |
| favorite | 实时删除（取消收藏） | — |
| report | 处理后保留 | 课程结束后归档 |
| notification | 标记已读 | 不主动清理 |

**说明**：由于是课程项目而非生产系统，未设计自动归档/定时清理任务。所有数据在课程周期（14天+评审）内保留即可。
